# 詞庫管理整合規格草案

狀態：討論稿 v0.2，依使用者回饋調整為沿用既有編輯流程，細節仍待討論。  
日期：2026-10-17。  
本次交付僅為規格文件，不修改介面、後端、詞庫資料或本機啟用狀態。

## 1. 目標與使用者需求

將內建詞庫的瀏覽、啟用與維護集中於既有「詞庫管理」頁。
使用者不必知道 Rime 的檔案位置或手動編輯 YAML，即可確認有哪些詞庫、目前是否啟用、
變更是否已生效，以及如何保留自己的修改。

典型操作：

1. 開啟詞庫管理，看見「台灣詞庫」與其來源、版本、詞數及啟用狀態。
2. 搜尋「發想」，查看讀音與基礎排序權重。
3. 停用詞庫，按「套用」完成部署，再確認生效狀態。
4. 對特定詞加入自己的讀音、隱藏來源項目或調整排序；後續更新仍保留這些修改。
5. 匯出個人修改備份，或將某一筆修改還原為內建值。

沿用「詞庫管理」既有的編輯體驗，讓內建詞庫成為可選擇管理的來源。
不再以另一套「內建詞庫編輯器」重複提供搜尋、選取、加入與修改功能。
讀音編輯、排序調整與備份細節仍須討論，但內建詞庫可編輯是本草案的基本方向。

## 3. 頁面資訊架構（建議）

保留「詞庫管理」為單一導覽入口與主要詞彙編輯區，使用來源選擇器切換目前管理的詞庫：

| 管理來源／工具 | 管理內容 | 主要操作 |
|---|---|---|
| 台灣詞庫（內建） | 隨程式提供的公開詞彙與個人修改 | 啟用、搜尋、加入、修改、隱藏、還原 |
| 個人詞彙 | 現有個人學習詞彙與精煉規則 | 沿用加入、修改、合併、封鎖與規則管理 |
| 使用者詞典 | Rime 實際學習與儲存的詞典 | 沿用備份、還原、匯出及匯入 |

選擇「台灣詞庫」或「個人詞彙」時，沿用同一個搜尋、詞彙清單與操作區。
來源摘要說明目前管理的是哪份資料；不因外觀共用而將不同資料混寫。
Rime 使用者詞典備份／匯入匯出保留為同頁工具區，不強迫將它偽裝成可逐詞編輯的來源。
不新增三個功能重複的編輯分頁。
個人學習開關與精煉設定維持原本職責，原設定頁可提供前往詞庫管理的連結。

資料列在窄視窗改為可閱讀的直向摘要，操作不依賴雙擊、懸停或滑鼠右鍵。

既有操作的接入規則：

- 加入、修改與多選操作沿用既有互動；內建詞彙有讀音需求時，在共用編輯表單中補充欄位。
- 選擇個人詞彙時保留目前的刪除、合併與封鎖規則，不改變它們的既有語意。
- 選擇內建詞庫時，「刪除」改為明確的「隱藏此項」，並提供「還原內建值」。
- 合併、封鎖及精煉規則只在適用來源顯示；不將個人精煉規則直接套到內建詞庫。
- 目前個人詞彙操作即時送出；內建修改需要部署。接入時必須清楚標示儲存時機，
  本期不默默改掉既有個人詞彙的即時儲存行為。

## 4. 詞庫清單與來源詳情

每個真正可以獨立啟用的詞庫顯示一列，至少包含：

- 顯示名稱、用途說明、版本、不同詞數與讀音筆數。
- 啟用開關、變更是否待套用、部署狀態及適用的輸入方案。
- 選擇該詞庫即可在共用清單管理詞彙，另提供「來源與授權」入口。
- 資源缺失或損壞的明確錯誤；不能將讀取錯誤顯示成「沒有詞庫」。

首版建議列出一個「台灣詞庫」，來源詳情列出 McBopomofo、新酷音與補充詞。
來源資訊不顯示獨立開關，也不宣稱能指出每個詞的唯一來源。
詞彙可能同時存在於多個來源，來源清單不能暗示互斥關係。

若希望「小麥注音／新酷音各自啟用」，需另行核定來源貢獻索引與詞庫重建規則。
單純切割成兩個擴充包可能改變重複詞處理及排序，必須重新驗證，不列為免費附帶功能。

來源詳情顯示來源名稱、固定版本、授權、詞頻轉換摘要、修改說明，以及隨附來源包的查看／匯出入口。

## 5. 啟用與套用語意

1. 切換開關只建立未套用變更，不立即暫停輸入法或重新部署。
2. 與既有頁面共用全域「套用」，一次處理多項詞庫及其他設定變更。
3. 套用前顯示影響摘要，例如「停用台灣詞庫；重新部署期間輸入法會暫停片刻」。
4. 一般啟停不另外要求確認對話框；不可用重複確認取代清楚的狀態提示。
5. 套用中防止重複送出；成功後重新讀取部署結果，失敗時保留未完成變更與可重試入口。
6. 取消變更回復最近一次儲存值，不觸及已部署檔案。
7. 明確停用後，升級與下次部署不得自行重新啟用。

狀態必須區分：

| 狀態 | 可表達的事實 |
|---|---|
| 待套用 | 畫面選擇與已儲存值不同 |
| 已停用 | 已部署方案不再掛載本詞庫 |
| 已部署，載入待確認 | 部署成功，但尚未確認服務已載入對應版本 |
| 已啟用 | 目前方案適用，且執行服務已確認載入對應詞庫版本 |
| 不適用目前方案 | 已設定啟用，但目前輸入方案未使用此詞庫 |
| 部署失敗／服務無回應 | 顯示具體失敗階段，保留重試入口 |

上述「已啟用」需要可靠的服務回報；若實作階段無法取得，應停留在「載入待確認」，不得由檔案存在推定。
不適用目前方案與服務未確認可同時存在，狀態模型不能僅使用一個 enabled 布林值。

停用提示：

> 停用後，這份詞庫不再提供詞彙；個人學習或其他詞庫仍可能提供相同的詞。

停用不刪除詞庫來源、授權檔、個人修改或個人學習資料。

## 6. 詞彙瀏覽

- 以詞彙及注音搜尋，支援完整詞與部分詞比對。
- 同詞多音分成不同資料列；詞與完整讀音為編輯識別單位。
- 顯示詞彙、注音、基礎權重／個人排序偏好、是否有個人修改。
- 原始權重屬進階資訊，不將它標示為「使用次數」或「你的詞頻」。
- 提供「全部／只看我的修改／已隱藏」篩選與總筆數。
- 15 萬詞量級使用分頁或虛擬清單，不將全量詞彙塞入 DOM。
- 搜尋時保留輸入焦點，過期回應不得覆蓋最新查詢；載入失敗與查無資料分別呈現。
- 首版不保證展示跨詞庫、個人學習與整句模型合成後的最終候選排序。

## 7. 內建詞庫接入既有編輯流程

原始內建詞庫維持可更新的公開版本；使用者維護內容以獨立個人修改紀錄保存。
部署時產生有效詞庫，不直接覆寫隨程式附帶的原始檔或公開詞頻。
這是共用編輯介面對應的資料儲存方式，不是新增另一個使用者操作流程。

| 操作 | 建議語意 |
|---|---|
| 新增詞彙 | 必須填詞彙與完整注音，不自動猜測專有名詞讀音 |
| 修改讀音 | 隱藏原本的詞與讀音組合，新增替代項；兩者在同一次套用生效 |
| 修改寫法 | 隱藏原項並新增替代詞與其完整讀音，不改動其他同形詞 |
| 隱藏此項 | 本內建詞庫不再提供這組詞與讀音；不表示全域禁止該詞 |
| 排序偏好 | 提供「降低／標準／提高」，實際權重轉換與上限須另外核定與測試 |
| 還原內建值 | 移除此筆個人修改，回到目前內建版本的資料；不表示回到舊版詞庫 |

排序偏好只調整基礎排序參考，不承諾固定第一候選，也不蓋過或重設個人學習紀錄。
個人詞彙頁的「封鎖」維持既有精煉與學習規則語意，不能冒充 Rime 全域候選封鎖。
本規格不新增全域封鎖功能。

停用整個詞庫時，其個人修改一併不參與輸入；再次啟用時恢復。
若使用者需要不依附本詞庫的自訂詞，應另議「自訂詞庫」，避免停用後行為不一致。

還原動作應可撤回。批次還原或刪除全部個人修改需顯示筆數與確認；不刪除公開詞庫檔案。

## 8. 更新、衝突與備份

- 更新只替換公開基底，保留個人修改與明確停用偏好。
- 個人修改優先於對應公開基底；不能以字詞文字比對而忽略讀音。
- 上游移除已修改的項目時，標示「原始項目已移除，請檢查」，不悄悄將舊讀音重新加入。
- 個人新增項目後來出現在上游時，去重並保留使用者的偏好，不重複加權。
- 公開資料與個人修改有獨立版本；部署結果記錄兩者版本，避免誤報已載入最新修改。
- 套用前驗證所有變更，再備份與寫入；部署及服務恢復失敗時回報階段與可恢復狀態。
- 新增「匯出個人修改／匯入個人修改」，格式包含版本與詞庫識別，不混用既有 Rime 使用者詞典備份。
- 匯入先預覽新增、變更、衝突與無效項目；不執行匯入檔案所含路徑或程式碼。
- 維護功能完全離線；本期不加入從任意網址下載或自動更新詞庫。

## 9. 後端與相容性邊界

以下為能力需求，非已存在的 API 或已核定命名：

1. 查詢內建詞庫清單、版本、來源、設定與部署狀態。
2. 分頁搜尋詞彙，讀取個人修改及有效值。
3. 將開關與詞彙修改納入全域待套用狀態，驗證後一次提交。
4. 產生有效詞庫、部署，並查詢服務實際載入的詞庫與修改版本。
5. 匯入、匯出及還原個人修改。

詞庫識別使用註冊清單，不接受前端任意指定檔案路徑。
編輯驗證至少涵蓋音節數與字數一致、合法聲調、音節可用性、重複項、換行與 Tab 注入，以及匯入容量限制。
最大詞長與可接受字元應以現有輸入方案及轉換器能力制定，不能直接沿用個人精煉頁的 40 字限制。

Windows 與 Mac 使用相同資料模型及介面，平台只負責目錄、檔案選擇、部署與服務查詢。
舊版設定只有 `enabled` 時須可直接讀取；若導入新格式，必須有明確版本及遷移備份。
個人修改不灌入 `PersonalLexicon` 的選字分數，也不直接刪改 Rime userdb。

## 10. 建議分期

### 第一階段：沿用既有詞庫管理，接入內建來源

集中到既有詞庫管理，加入來源選擇、整包開關、來源授權與真實狀態呈現。
內建詞庫接入同一套搜尋、加入、修改、多選、隱藏與還原操作；以個人修改紀錄保護更新。
必須同時處理讀音驗證、部署及更新衝突，不以唯讀清單代替使用者期待的編輯功能。
沿用目前合併詞庫，保留現有個人詞彙與使用者詞典工具。

### 第二階段：依討論結果補充進階維護

排序偏好、個人修改匯入／匯出及進階批次操作可依實際需求分期。
基本加入、修改與隱藏不另起一套編輯介面。

### 第三階段：視需求另議

按來源獨立啟停、自訂詞庫、試打區與候選來源追蹤。
不預先承諾線上更新或一般用途詞庫商店。

分期為建議，進階維護的交付範圍尚待確認。

## 11. 驗收條件

1. 從「詞庫管理」即可找到內建台灣詞庫，不需要知道 Rime 目錄。
2. 詞數與版本來自目前資源，且能看見授權與來源包。
3. 停用／啟用與全域套用一致；跨頁保留未套用變更，取消可恢復。
4. 部署成功、服務未回應及不適用目前方案有不同提示，不以成功寫檔冒充已載入。
5. 停用後再升級或重新部署，不會自行啟用，也不刪除個人學習紀錄。
6. 有其他來源或個人學習時，停用提示能解釋為何仍可能看到相同詞。
7. 開關與瀏覽內建詞庫不依賴 LLM 模型或個人精煉功能已開啟。
8. 沿用既有編輯流程即可修改內建詞彙；同詞多音可分別修改與還原，更新保留修改，重複詞不相加。
9. 部署失敗不遺失原資料，服務能恢復，且可定位失敗階段；若提供匯入也須符合相同要求。
10. 詞數量級下搜尋與切頁不阻塞介面；鍵盤能完成搜尋、選取、修改及套用，狀態不只依顏色辨識。
11. Windows 與 Mac 分別驗證部署及載入；僅通過共用程式測試不能宣稱 Mac 實機已生效。

## 12. 待討論決策

- 編輯沿用既有詞庫管理；待確認的是進階排序與匯入／匯出的範圍，不再以「要不要做另一套編輯器」為決策。
- 啟用粒度：先保留一個合併台灣詞庫，或要求小麥注音與新酷音獨立切換？建議首版整包。
- 排序偏好：是否首版提供降低／提高？其映射值與生效範圍須先以同音詞及整句測試定案。
- 來源選擇器與使用者詞典工具區的配置是否直覺？目前建議共用編輯區，保留獨立的備份／匯入匯出工具。
